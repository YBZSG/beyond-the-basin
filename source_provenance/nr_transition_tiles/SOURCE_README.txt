一、这次实际修改
1. RT 材质转换从“每批新物体重新扫描所有常驻房间”改为“只检查新增批次”。同一材质只处理一次、已正确的 shader 不重复赋值，释放中的房间通过弱引用排除。真正切换 RT 开关时仍完整转换，保留四类已有 RT/光栅材质。
2. NR 增加 1–4 层、混合强度、局部色调、结构细节设置，默认仍为 1 层、1.0 / 0.1 / 0.5。设置保存，NR 与帧生成互斥。旧引擎无法确认新接口时新参数禁用，不把菜单数值当作已生效。
3. 提供对应的定制引擎增量补丁：每层独立 feature/history/output；完整链成功才报告已执行。切层/分辨率时安全重建，失败保留原画面。多层共用原始深度和运动矢量，是明确的近似，层数越多不保证更好，反而增加延迟与显存。
4. 瓷砖使用已有 ORM 的线性 alpha 覆盖区分砖面与砖缝，避免根据过滤后的粗糙度猜砖缝。砖面低但非零粗糙度、非金属，砖缝保持粗糙；保留最新的细碎面法线/砖边凹缝法线分离，不把整面做成镜子。
5. 复制诊断中增加 RT 转换计数/耗时、NR 请求与实际状态。没有替换原水体、风纹、大水波或用户的自定义渲染器。

二、怎样安装
请先关闭 Godot 编辑器和游戏，保留你的原项目备份。
把本 ZIP 解压到项目目录之外。需要系统已有 Python 3，安装器不下载软件。
在解压目录打开终端，先只检查（把路径换成含 project.godot 的工程目录）：
python Apply-Update.py "D:\你的PoolCore工程" --check
通过后应用：
python Apply-Update.py "D:\你的PoolCore工程" --apply

安装器逐文件核对原版 SHA256。发现不同版本或本地编辑会在写入前拒绝，不强行覆盖。不要用手动覆盖绕过冲突。若远程以后更新，请先合并审查。
原文件保存在工程 .poolcore-updates/nr-transition-tiles-20261024-01/original。其他文件保持原样。
需要回退且更新后的文件没有再修改时：
python Apply-Update.py "D:\你的PoolCore工程" --rollback
新增文件会移动到备份目录保留，不永久删除。

三、NR 不会仅靠源码覆盖就获得新功能
已有的定制引擎继续运行旧单层 NR，新控件会清楚显示未确认支持。
要运行 1–4 层，需要按 tools/dlss/NR_README.md，用匹配的 NVIDIA Godot 固定提交及已有合法 SDK 重新编译。所有旧引擎补丁仍保留，新 engine-dlss-nr-controls.patch 放在最后。
本包没有引擎、SDK、DLL、PCK，也没有代替你接受新的 SDK 协议。不要在普通 Godot 4.6 上以菜单出现判断 NR 工作。
编译后的第一次测试保持 1 层，先看“原生已执行”状态和日志，再试 2 层。3/4 层仅为实验。NR 关闭停止计算，但缓存显存保留到重建/退出，并非立刻释放全部显存。

四、已验证和未验证
已完成：官方 Godot 4.6.3 的脚本解析、设置/保存/旧引擎禁用逻辑、1280×720与1920×1080菜单布局尺寸、真实生产房间的 CPU 材质/碰撞/流式合同测试；原始导入贴图 alpha 确实保留；独立 NR 资源生命周期代码审查。
NR 原生补丁只做了补丁上下文合同、独立数值 C++ helper 编译及源码测试，未编译整个定制 Godot/NGX，也未在 NVIDIA 显卡执行。
云环境没有可用图形显示，创建显示套接字被限制。因此本轮没有新的真实游戏图片、NR 多层动图或瓷砖视觉 A/B；本包不宣称写实视觉已达标。
真实 Expanded 房间的局部 CPU 对照（官方4.6.3无图形）：5个新外壳批次，旧全场扫描平均6.411ms，新增量队列+转换1.415ms；之后5个内部批次，旧5.084–7.064ms，新0.049–0.095ms。每批交替测8次，同一组真实材质和房间，结果一致。这些数值不包含水体/GPU渲染或整帧。
没有测你的 Windows 帧率、GPU耗时或显存。CPU 局部转换优化不等于整个跨房间果冻/低帧问题已解决。BLAS、着色器编译、反射刷新及水体完整链仍需目标引擎分析。
已有主渲染目标销毁后 NR 锁定目标自动重选问题仍未解决。

五、明确不默认启用的房间分帧实验
tests/room_transition/ 下保留了独立分帧源码快照/差异及检查。它把房间外环生成分散到几帧，但总工作不消失，且更换 pool_world.gd 会使原水地形/快照缓存失效。
本更新不应用这个实验，生产 pool_world.gd 保持原版字节，不弱化缓存校验。不要将实验文件自行替换后误以为缓存仍有效。
