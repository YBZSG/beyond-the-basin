# 房间卡顿修复与主厅收口

2026-10-21，Godot 4.6.3 / Forward+。这是现有完整项目的修复，不是另做一个演示房间。原交付包保持不变。

## 已定位并修复的阻塞

原版每次跨过房间边界，都在主线程重新收集全部静态建筑、构建约10万三角形的BVH，以及计算两张256²入射遮挡图。即使三个房间都已加载，回房也重复计算。实际原版运行记录：初次7.582秒；暖往返仍分别4.859秒和6.892秒。

现在：
- 几何快照仅在建筑版本改变时收集；原深度、BVH、湿区、遮挡计算移到后台线程，完成后一次发布，不显示半成品遮挡图。
- 按房间、几何版本、波场分辨率缓存；正式三房提前准备。邻房准备期间保留原有效96m波场，原碰撞始终保留。
- 初次水深未准备完时显示可响应的准备状态，暂不放开玩家与浮动物体。远距离传送超出旧域时同样等待，不把未知水深伪装成有效数据。
- 六面1024²线性HDR环境捕获改为异步读取，mip计算移到工作线程；相同房间复用完整Cubemap，最多缓存六房。
- 同尺寸BVH GPU缓冲区更新而不反复销毁重建。原整数波场平移改为无过滤的原生RF内存拷贝，逐字节保持原结果。

原仓库SWE、细波纹、MPM、光子折射/Jacobian焦散和交互方程未被低配近似替换。CPU准备、整数平移、HDR面及所有mip都与旧路径做了精确数据对比。

## 实际连续走门验证

不是传送测试：相同控制器、120Hz物理、四次穿过主厅与拱廊连接坡道，最大单物理步水平位移约2.12cm，三个房间始终驻留，未重建、未退休、未穿落。

| 测量 | 原交付版本 | 本次修复 |
|---|---:|---:|
| 暖出门静态水体主线程准备/提交 | 4,859 ms | 2.344 ms |
| 暖回房静态水体主线程准备/提交 | 6,892 ms | 2.386 ms |
| 暖出门最大实际帧间隔 | 8,306 ms | 1,405 ms |
| 暖回房最大实际帧间隔 | 10,420 ms | 1,472 ms |

环境是云端Linux llvmpipe软件Vulkan，640×360输出但完整High水体、1024反射、4096阴影和GI。不是Windows硬件基准，不能将这些数字换算成你的PC帧率，也不声称已经60FPS。固定5Hz仅用于确定性控制时钟；表中的毫秒来自真实墙钟。每个暖行走段只有9个绘制样本，p95/p99接近最大值，不能当作长时间统计。

修复路径最终3次后台准备、4次地形缓存命中、3次Cubemap缓存命中；六面捕获仅做了两房的12面。整段GPU缓冲分配数量保持不变，后续4次使用原缓冲。房间处理函数最大7.147ms。记录见 docs/verification/transition-before/after.json、日志、逐帧CSV及方法说明。

比较运行使用相同的已导入建筑SCN；运行时光照/材质已调整，因此整帧改善不是纯缓存单变量实验。之后才导入新的收口GLB并拍摄画面，其碰撞219个代理逐字节不变。

## 主厅画面改动

- 修正把采光玻璃作为实心发光板挡住日光的问题；玻璃透光，实体窗框和洞口仍遮光。水体光学BVH也明确排除透明玻璃，而非只改Godot阴影开关。
- 正式房间的daylight标记生效，进入拱廊/侧池不再被旧房型编号误关太阳。
- 用真实顶窗方向光和克制洞口补光替换八盏覆盖全厅的强补光；保留原水体两个有效光源的顺序、位置和功率输入。
- 干走道、浅水池底、墙裙和压顶使用不同陶瓷响应，仍保留2K扫描颜色、OpenGL法线及粗糙度，约10cm砖尺度不变。
- Blender主厅增加齐平浅色台阶鼻口、44条压顶分缝、墙裙/柱脚收口，合并为两个新网格批次。保留可编辑.blend和生成脚本，其他房间不改动。

## 仍然存在的限制

第一次启动仍需编译/上传GPU资源；第一次未缓存房间仍需捕获环境图。Cubemap最终上传在云端约50ms，尚不是完全无卡顿。原始源算法的GPU成本仍较高，保留High，不擅自把用户设置改成Low。

SDFGI仍不是离线多次反弹光照，材质/建筑也仍需更多美术制作，不能称为已达到照片级写实。原生mip Cubemap仍不同于Three的GGX PMREM；硬BVH阴影仍不同于源PCF。整项目退出仍有7个Texture RID警告，与原交付包一致，本次没有冒称已消除。

原种子生成世界保留，但本轮真实GPU四次走门性能验证针对默认正式三房；legacy首次新增建筑仍存在同步场景实例化工作。Windows用户机器和新水体Android路径没有本轮真机验收。

## 启动与反馈

完整解压Play ZIP。把官方Godot 4.6系列EXE放到PCK旁，双击Launch-PoolCore.cmd，或把已有Godot EXE拖到脚本上。脚本支持带空格/中文路径，不强制改名、不重置设置、不自动下载或上传。它记录引擎版本、输出及退出码，失败保留窗口。

G键显示诊断时可看到地形提交耗时与缓存命中。若仍卡顿，请保留本轮生成的诊断TXT和引擎LOG，并说明是首次进入、回到已去过的房间还是站着不动也慢。日志可能含本地路径与显卡信息，可以先检查。

## 本包导出检查

完整导出的PCK在项目目录之外使用Godot 4.6.3 / Forward+ / llvmpipe启动，等待真实地形与HDR环境图准备完成后触发一次源拍水。实际捕获1180×663，三个房间与六个道具存在；地形、平面反射、环境Cubemap、入射遮挡均ready，原MPM累计模拟13,806个粒子步骤、液体绘制10帧、6次回水波纹，无水体运行错误，进程退出0。该数字仅证明原交互管线仍在运行，不代表性能或画质等级。

退出仍有7个Texture RID警告。导出器在写完PCK后记录了保存空路径编辑器设置的警告，但导出退出0，所生成的同一PCK已实际独立运行验证；未将该警告误称为资源缺失。Windows启动CMD仅做静态检查，本环境不能声称执行过Windows CMD或用户显卡。
