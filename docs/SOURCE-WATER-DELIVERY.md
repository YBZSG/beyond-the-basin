# PoolCore 原仓库水体移植交付说明

更新：2026-10-21。

后续修复已改为后台准备和缓存，本文后面的同步遮挡等待描述为原交付历史，现以 [房间卡顿修复说明](ROOM-TRANSITION-FIX.md) 为准。

目标：**Godot 4.6.3 Standard、PC、Forward+**。

本次水体依据原仓库提交 **`66a4543602d9e774db07c2da12ce1d40d522532c`** 移植，不是后续 V2 工作副本，也不是用另一套正弦水纹模仿外观。原有 Three 项目没有被替换。本说明覆盖旧 README、`native-parity-review.md` 中“GPU SWE / MPM / 光子焦散尚未移植”等历史描述；那些文档保留作此前版本记录，不能代表本次水体状态。

这是可继续编辑的原生移植版，**不是已经完成照片级写实的成品，也不声称整个渲染器逐像素等价**。

## 1. Windows 启动

1. 从 [Godot 官方 4.6.3 下载页](https://godotengine.org/download/archive/4.6.3-stable/) 选择 **Windows x86_64 / Standard**，不需要 .NET。
2. 解压完整源码项目，在项目管理器中导入 `project.godot`。等待首次资源导入和着色器编译完成，保持 **Forward+**，按 **F5**。
3. 默认进入正式三房：**采光主池厅、连续拱廊、静水侧池**。默认 High 水体为 768² 浅水场与 768² 细波纹场；首次房间环境捕获较慢。

若使用单独的游戏包，`PoolCore-Source-Water.pck` 不是可独立双击的 EXE。将其与解压后的官方引擎放在同一目录，在该目录的 Windows 命令提示符运行：

```bat
Godot_v4.6.3-stable_win64.exe --main-pack PoolCore-Source-Water.pck --rendering-method forward_plus
```

完整项目中的 PCK 输出位置为 `output/windows/PoolCore-Source-Water.pck`。运行已有 PCK 不需要安装导出模板；重新导出 Windows EXE 才需要匹配的 4.6.3 模板。若另行导出非嵌入式 EXE，应将 EXE 与其同名 PCK 一起保留。不要把以前交付的 EXE 或 APK 当成本次新水体构建。

本管线需要真实图形上下文和 RenderingDevice。**Compatibility、纯 headless 启动不能验证或运行完整 GPU 水体**；程序不会悄悄换回旧 CPU 水场来冒充成功。遇到系统安全拦截，不要关闭系统安全功能，可用官方引擎打开源码项目。

### 操作与旧世界

- WASD 移动，Shift 奔跑，Space 跳跃；E 拿取/放下或攀梯，W/S 攀梯。
- 左键拖动物体或拍水；右键按住蓄力、松开投掷；滚轮调整持物距离。
- R 返回起点，Esc 菜单；H 隐藏界面，G 诊断，V 间接光，C 焦散，F 镜头风格，F11 全屏。
- 菜单可切换房间、质量和水体参数。正式主池水深 0.44 m，应是踩底涉水，不是自动游泳。
- 原 **32 m 网格、11 类房型、种子/WFC、5×5 流式生成世界**仍保留，非默认入口。在启动命令末尾加 `-- --legacy-world`。例如：

```bat
Godot_v4.6.3-stable_win64.exe --main-pack PoolCore-Source-Water.pck --rendering-method forward_plus -- --legacy-world
```

正式三房是重新制作的场景资产，不是原提交中的三间房逐字节复制；其可编辑 Blender 文件与 GLB 一并保留。水体算法的来源和房间美术的来源应分别理解。

## 2. 原版与当前实现对照

“保留”指源方程、主要数据布局或行为得到移植并有相应测试，不等于跨 API、驱动和浮点实现位级一致。

| 系统 / 原版 `66a4543` | 当前实现 | 差异或边界 |
| --- | --- | --- |
| GPU 浅水 SWE | 原速度、高度、泡沫、湿干边界、地形、压力/动量注入和读回；96 m 域，384–1152² 质量档 | WebGL 片元阶段改为 Godot 全局 RD compute；显式 binary16 最近偶数舍入，避免已测驱动截断偏差 |
| 交互细波纹与微法线 | 48 m 独立动态细波纹场；原带限微法线、距离/足迹过滤 | 细波纹仍不参与浮力；不是把解析环纹冒充求解器 |
| 水面折射 / 吸收 / Fresnel / 浮沫 | 源 Snell、Schlick、Beer、厚度/前景拒绝、泡沫输运与着色表达式移植 | Godot reverse-Z、屏幕坐标和 HDR 输出适配；最终色调映射非 Three 全链路像素等价 |
| 不透明场景色与深度 | Godot 当前帧 opaque copy，透明基础水面不回采自身 | **不是原版可跳帧的折射捕获节奏**；`refractionRefresh` 未伪装成有效滑条 |
| 平面反射 | 真正镜像相机、房间捕获、反射投影及线性 HDR | 用 SubViewport；原 oblique projection 裁剪改为对应世界平面着色器裁剪。纹理与投影矩阵现在同帧配对发布；相机移动、转动或投影变化强制刷新，静止跳帧时保留同一对数据。关闭镜面捕获的 TAA，未加模糊、未改源水波/法线方程。非原 WebGL render target |
| 光子焦散 | 原光子网格经实时水面折射/反射，落在接收面，按导数 Jacobian 聚焦；保留入射 AABB、出射三角 BVH 遮挡、滤波与 mip | GPU 原生光栅/缓冲接口不同；不是预烘图或正弦焦散贴纸，也不是无限反弹光路追踪 |
| 焦散房间适配 | legacy 保留 ±15.7 m 原墙面；正式房间显式设置反射墙/水池壁位置 | 只调整接收平面偏移，保留源图集尺度及光学方程；仍非任意曲面通用接收器。首次房间构建同步完成同一入射遮挡计算，避免 GDScript 的 2ms 渐进预算留下未完工图；本次云端增加约3秒初始化等待 |
| MPM / APIC 三维飞溅 | 3 域，每域 18,000 粒子、80³ 网格、1/720 s 子步及原 9 阶段；邻接、压力、黏性、各向异性形状保留 | 无降为粒子纸片或弹道替代；跨 GPU 编译器数值按原容差验收，不宣称轨迹逐 bit 一致 |
| 液片表面合成 | 原各向异性几何、眼空间深度、四次窄范围滤波、折射/遮挡与水面接合 | Godot CompositorEffect 取代原 pass 编排，原始 HDR 与读写目标分离保留 |
| 次级水滴 / 气泡 / 回落 | 原 1,024 容量、空气阻力/重力、气泡上浮、扫掠接触、体积相关回波及一次性回收 | 浸水气泡材质由 Godot BRDF/环境实现，不是 Three MeshPhysicalMaterial 完全复刻 |
| 浪尖和环境扰动 | 原扫描门限、30 Hz 扫描、随机概率、每次最多 12 次发射、环境细波纹节奏 | 保留原行为边界；没有额外虚构的独立喷泉发射器 |
| 物体与水双向耦合 | 原浮力常量、坡度力、Stokes 漂移、相对水流阻力、尾流/压力偶极和入水方向 | 原生刚体接触与旋转仍是 Godot/Jolt。静态地形/BVH 收集现排除 RigidBody3D、CharacterBody3D 及其子树，避免道具把自身水格误烘成干地；修复后 144 帧、864 次道具采样均在水内，未改源浮力公式 |
| 玩家涉水 | 原按实际行进距离注入动量、分段脚步、压力偶极、落水事件 | 控制器保留 CharacterBody3D 原生碰撞；眼高 1.6 m，并非原相机物理一比一替换 |
| 房间环境反射 | 捕获实际房间六面线性 HDR Cubemap，不是固定天空替代 | **原生 mip 链不等于 Three PMREM / CubeUV 预滤波**，粗糙反射仍有差异 |
| 液片/水滴直接光阴影 | 27 灯容量；原前四阴影槽用实际三角 BVH，保留源偏移及透视深度 bias 解释 | **硬中心射线可见性不等于原 1024² cube shadow 的半径 2 PCF**；动态投影物、材质 shadowSide、逐顶点法线偏移仍有边界，移动物体不会自动进入静态 BVH |
| 世界、场景、材质 | 正式三房为默认；主池 4 个、侧池 2 个合法水内道具点，干拱廊不放漂浮道具；legacy 种子生成规则不变 | 正式场景新增美术；32 m 世界的绝对坐标没有整体浮动原点，水域局部 rebase 不等于全世界精度保障 |
| GI、建筑灯光与后期 | Godot SDFGI / SSIL / SSAO、原生灯光、阴影、雾和色调映射 | 非原体素/GI、矩形 LTC、实验烘焙与浏览器后期逐算法移植；写实灯光校准仍需继续 |
| 菜单、音频、诊断 | 原生操作与设置、水体参数/12 视图、17 个 OGG 和水交互路由保留 | UI 非 React，混音非原 Web Audio 图；浏览器 GPU 阶段记录器/后端切换未复刻 |
| Android | 旧触控、Mobile 设置及导出源码保留 | **本次新 GPU 管线没有完成 Android 验证，没有交付新 APK**；桌面测试不等于手机通过 |

保留原版的一处重要行为：玩家直接涉水 `crest` 请求最多 0.22，而原 MPM 门限为 0.28，所以该请求本身不会生成 MPM 域。涉水仍有尾流/波纹，后续满足条件的浪尖扫描或足够强的入水事件可以产生飞溅。这不是偷偷放大强度后宣称“精确移植”。液体 CPU 接触也仍读取原式过滤宏观水面，不是同步读取每个着色细波。

## 3. 已验证到哪里

以下是实际代码和运行记录，不是仅看截图推断：

- SWE：27 项接口/地形断言、13 个 CPU 参考用例；真实 Vulkan 35 项 GPU 比较无失败；独立全局设备/异步读回/释放测试通过。小网格测试只证明相应用例，不证明全分辨率性能。
- 原事件桥：538 项断言；玩家/物体耦合：16,057 项比较无失败。控制器在 30/60/120 渲染采样下各 37 项通过，物理 120 Hz。
- MPM：4 组原始初始化缓冲 SHA-256 完全匹配；生命周期 7 项、接触 8 项、实际 GPU 重力/APIC/孤立形状/压力扩张 4 项通过。HDR 像素检查90帧通过，覆盖深度遮挡、非零域原点、折射方向和直接光 BVH 遮挡。
- 焦散：真实 HDR 光子光栅、墙面反射/透射、独立入射/出射遮挡及 mip 通过；7 个 GPU 采样与独立光学参考最大相对误差约 0.519%。这不是全场景物理正确性的证明。
- 平面反射：实际投影颜色位置、水下裁剪和 HDR 峰值 4.0 通过。新增静水移动相机测试：逐帧及运动强制刷新的隔帧档位，对位误差均≤1.105像素；静止相机+实际波动测试保留非零变化。见 `REFLECTION-TEMPORAL-FIX.md`。
- 正式资产导入通过；最新目的地与连续移动测试 **10/10 通过**，覆盖三个目的地出生高度、四级台阶上下、0.44 m 踩底涉水、主厅至拱廊/侧池与外围碰撞。旧失败记录不代表修正后的结果。
- `tests/source_static_terrain_test.gd` **17 项通过**：静态建筑仍参与地形/遮挡，动态道具与玩家不再误进入静态场，相关水格保留 0.44 m 水深，六个正式道具点均在水池内、干拱廊为空；新增负向用例确实复现了旧收集方式造成的“自身水格变干”。记录：`verification/source-static-terrain-final.log`。
- 最新实际连续运行 **144 帧**，每帧六个道具，共 **864 个水内采样，零干地/坠落道具**；物体高度相对“实际局部水面＋原版种类浮高”的最大偏差 **0.017124 m**，最低物体中心高度 **0.313125 m**。末帧近处鸭子 y=0.444974 m、鸡蛋 y=0.320075 m。**131 帧玩家涉水，144/144 帧遮挡掩码完整**。这是修复后的真实运行证据，不再仅是静态回归；六秒记录仍不等于长期稳定性测试。
- 主场景已有一次真实 GPU 集成记录：13,806 个 MPM 模拟粒子、7 帧液片合成、48 次回收、6 次回波，房间 Cubemap 与平面反射就绪，水体错误字段为空。短测不替代长时间压力测试。
- **最终 PCK 已在项目目录之外通过 `--main-pack` 实际启动并正常结束测试**，包含最新反射、静态地形及道具修复：六个道具、Forward+、High、768²、GI 开启、水体就绪、入射遮挡完整、平面反射与 Cubemap 就绪，水体/液片/焦散错误字段均为空。退出仍有下述已知 Texture RID 警告；这不构成 Windows 显卡验收。

测试机是 **Linux Godot 4.6.3 / Mesa llvmpipe 软件 Vulkan**，并非 Windows 独立显卡。部分隔离 RD 测试用了桌面 Mobile 渲染器，也不表示在 Android 设备运行过。Windows 输入、音频、显卡驱动兼容和长时间运行尚需目标 PC 验证。

High、GI 开启、无活动 MPM 域的一次主厅 24 帧实测中，后段约 **1.5–2.0 秒/帧**；含启动/环境捕获均值约 **6.24 秒/帧**，P95 约 **33 秒**。这只是软件 GPU 上的实时时钟间隔，不能外推 Windows GPU 性能，更不能宣称 60 FPS。固定模拟步长和视频播放帧率也不是实际渲染帧率。

最终 PCK 独立启动的 14 帧样本含预热，均值 **3489.383 ms/帧**、P95 **14314.295 ms/帧**。两组数据的场景阶段和样本长度不同，不用于宣称性能提升；均不是目标 PC 硬件结果。

完整主场景退出仍出现 **7 个 Texture RID 未释放警告**。恢复出的移植前原生导出运行日志已有相同警告，因此没有证据证明是本次水体新增，但也不能因此当作已修复。独立液体测试没有复现，不等于整场景生命周期验收通过。

仍待专项验收：长时间多域交互、持续资源增长、活动液滴/待读回时的实际 GPU rebase 压测、动态投影物 BVH 更新、深度滤波全套原版 GPU 图像 A/B、目标 PC 视觉/音频和最终写实观感。
