# 重做池厅：路线与可编辑资产

## 进入与游览

首次启动仍默认进入原仓库场景。按 Esc，在“出生地 / STARTING WORLD”选择“重做主池厅 / FORMAL HALL”，点击“在此出生”；选择会保存。也可用启动参数 `-- --formal-hall`，或用 `-- --original-world` 返回原场景。两套世界和原有互动均保留。

五个房间由真实的门洞、走廊和坡道连接，不需要传送。这里“北”是世界 −Z，“东”是 +X，房间网格间距为 32 米。

1. 采光主池厅 `(-1,-1)`：22 × 20 米，池边干燥步道通向三个出口。北门去穹顶静浴，东门去连续拱廊，南门去静水侧池。
2. 穹顶静浴 `(-1,-2)`：圆形池、环形步道和天窗；南门回主厅，东门去浅水天井。
3. 浅水天井 `(0,-2)`：20 × 18 米，真实开敞采光口和 0.22 米深的浅池；西门回静浴，南门去拱廊。
4. 连续拱廊 `(0,-1)`：24.8 × 6 米的干燥连接空间；北侧分支去天井，西门回主厅。壁面服务柜是封闭建筑细节，不是可开启的门。
5. 静水侧池 `(-1,0)`：14 × 14 米的安静支线，西侧有固定座凳；北门原路回主厅。

推荐完整环线：主厅沿池边步道到北门 → 静浴 → 天井 → 拱廊 → 主厅，再从南门探访侧池。池厅之间不要把“朝向下一个房间”理解成必须直穿水池。所有主步道标高为 +0.52 米，水面为 +0.32 米；连接坡道会下降到网格交界的 −0.72 米再上升。

环线已用原生玩家控制器连续验证：52 段行走、30,476 帧，没有断路或失去地面。另有 80 次走廊侧向冲刺/跳跃和 12 次完整跨越的围护检查。这些是通行证据，不替代画面验收。

## 编辑与重建

- 五个房间分别对应 `formal_mainhall`、`formal_bath`、`formal_terrace`、`formal_arcade`、`formal_sidepool`。另有独立 `formal_arch` 构件，所以交付是六份模型，不是六个房间。
- 可编辑 Blender 4.3.2 源文件：`tools/blender/source/formal_*.blend`。生成器：`tools/blender/build_formal.py`。运行时模型：`assets/models/formal/formal_*.glb`。源目录的 `.gdignore` 必须保留，Godot 使用 GLB，不自动转换 `.blend`。
- 不改动生产资产的复现命令：`python3 -B tools/blender/verify_formal_delivery.py --work-root /tmp/formal-delivery-check`。使用项目外的空目录。已验证六份生成器输出和六份直接从交付 `.blend` 导出的 GLB 均与生产文件逐字节一致。
- 确实要修改并替换一个模型时：`blender -b --python tools/blender/build_formal.py -- --only formal_mainhall`。先保存检查点。同步检查 `formal_manifest.json`、房间目录及水中阶梯描述，再重新导入、验证通行和水深，并重建受影响的缓存与灯光烘焙。不要混用旧烘焙与新模型。
- 米制 UV0、UV2、材质角色及每个 `COLLISION_` 局部代理都属于交付契约。不得把整座拱、整圈池壁或整段阶梯合成一个凸包。静水面由运行时负责，不要向模型加入假的水面来代替模拟。

尺寸、碰撞归属、材质映射、精确复现和来源说明见 [资产交付指南](../tools/blender/FORMAL_ASSETS.md)。这些是项目原创几何；保留现有项目与第三方许可说明，不另行赋予或声称新的资产再分发许可。
