# PC 帧生成与硬件光追 — 0.6.8

Esc → 桌面画质中新增 NVIDIA 帧生成 2×（自动配合 Reflex），以及“原泳池硬件路径追踪 + 光线重建（实验）”。帧生成初始开启，实验光追初始关闭；保留玩家已保存的 DLSS 档位和水面设置。两项都支持保存、关闭和设备不支持时回退。关闭 DLSS 会停用依赖它的帧生成和光追；重新启用后恢复保存的选择。

光追使用 NVIDIA Godot 实验引擎的 Vulkan 硬件加速结构与路径追踪管线，主视图采用每像素 1 个采样、3 次反弹和 DLSS Ray Reconstruction。建筑、人物等不透明几何使用路径追踪；透明水面仍使用现有波浪、折射、平面反射与焦散。它不是完整的水体路径追踪，也没有新增水花粒子。

目前仅适配原泳池场景。切换到另一套场景时保持常规渲染，菜单会说明原因。普通 Godot 4.7、缺少合适 NVIDIA 硬件或运行库时回退。帧生成和光追分别查询显卡能力，不按显卡名字猜测。此功能只用于电脑版，不改 Android 工程。

## 兼容修正

修复 NVIDIA 分支光追输出/法线纹理格式不一致、fragment discard 未正确进入 any-hit、切换渲染模式后旧 FG context 没有及时停用，以及退出时人物 BLAS 重复释放。为瓷砖和建筑提供保留原贴图参数的 RT 材质，处理屏幕导数、纹理 mip bias 和法线变换。切换同样作用于材质库，供后续加载的房间继承。房间探针和平面反射使用原来的渲染方式。

## 验证方法和限制

本机 RTX 5070 Laptop 8GB、驱动 621.01，1920×1080，Vulkan Forward+。所有检查复制用户配置到独立 APPDATA，未覆盖真实配置。正式 EXE 基准固定原泳池视角，Ultra 自定义设置、Balanced、道具冻结，预热 120 帧后统计 360 帧，无截图回读或后台编译。基础 FPS 来自真实帧间隔；呈现 FPS 另取 NVIDIA 运行库实际呈现计数。后台窗口可能暂停额外插帧。

帧生成增加画面呈现帧数，同时会占用 GPU；操作响应仍受基础帧率约束。此数据是单机固定视角短测，不代表全地图和其他显卡。静态截图记录的是渲染帧，不能验证所有插值帧；快速转向、水面高光和 HUD 的插帧瑕疵仍需长期游玩评估。首次打开光追会编译材质，短暂使用默认材质可能有闪变。原有退出时 7 个 Texture RID 泄漏警告仍存在。

旧 DLSS 版完整保留，可通过旧目录启动器回退。本次本地交付，没有上传 GitHub。

## 正式 EXE 实测

| 模式 | 基础渲染 FPS | 呈现 FPS | 帧时间 P95 |
| --- | ---: | ---: | ---: |
| DLSS Balanced | 47.03 | 47.03 | 22.18 ms |
| Balanced + 帧生成 2× | 41.29 | 81.82 | 25.78 ms |
| Balanced + 帧生成 + 硬件路径追踪 | 39.87 | 79.33 | 27.53 ms |

呈现计数使用测量区间内完整的 120 游戏帧窗口，舍去第一个可能跨越预热阶段的窗口。全程窗口获得焦点。正式模板不输出编辑器专用 TLAS 统计；同一 PCK 在配套编辑器运行时记录了 2691 个 TLAS 实例，正式 EXE 则核验 RR 调用成功、无渲染错误及实际画面。

同一 PCK 通过 FG/RT 开关、关闭 DLSS 后的回退、1600×900/1920×1080 缩放、设置重载、跨房间和 2.08 m 淌水检查。测试记录在 `output/dlss/fg-rt-final-controls`、`fg-rt-final-raster`、`fg-rt-final-fg`、`fg-rt-final-rt`。标准 Godot 4.7 的不支持回退检查通过。
