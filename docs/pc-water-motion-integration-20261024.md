# PC 动作与手部整合 0.6.9

版本：0.6.9-pc-motion-fg-rt-20261024。

采用用户提供的 Water Motion Editable Assets / Code Tests 两包中的人物动作、手部、缓坡脚部修正与菜单展示。来源文件及原作者验收范围保存在 source_provenance/water-motion-20261023/；制作 GLB、Blend 与脚本保留在 assets/water_motion、assets/water_hands 和 tools/blender 对应目录。

## 合并范围

- PC 使用自包含的 explorer_water_motion.scn，共 54 骨、14 个动作。原 42 骨静止姿态不变；保留当前衣物材质处理、第一人称头部隐藏和反射裁切。
- 新增蛙泳、踩水、起跳/滞空/落地、蓄力/出手/恢复动作；控制器负责位移与投掷，动作只跟随真实物理状态。支持 --legacy-water-actions 回退。
- 手指根据持物尺寸做有限姿态适配，腕部辅助跟随最终 IK 姿态。脚部只修正连贯且最多 30° 的缓坡，平地快速跳过；不是通用楼梯 IK 或完整脚部锁定。
- 新菜单保留现有 DLSS / FG / RT 的节点、信号与配置；没有复制朋友包中的水花菜单。普通保存现在会先读取旧配置，保留其他功能的未知字段。
- 保留本地整段大水波交互：推水系数 1.65，脚步 wave_impact ×4，wake_dipole 宽度 0.62，以及前移的落脚点。没有引入 local_splash_particles、对应 shader 或 source_water_runtime/settings 改动。
- Android 工程与导出未更新；PC 展示和动作有移动端绕过。此前的 DLSS、FG 与实验硬件路径追踪保留，光追默认关闭，透明水面继续原渲染。

## 打包

PC 导出显式包含 assets/water_hands/hand_pose_contract.json。运行时使用 SCN，制作 GLB、Blender、测试和验证图片不进入发行 PCK。使用原有 NVIDIA Godot 4.8-dev 固定引擎与匹配模板，没有重新替换引擎或改动 SDK。

## 已完成的验证

所有本机运行使用独立 APPDATA。NVIDIA RTX 5070 Laptop，驱动 621.01。

- 60 Hz Jolt 控制器 75 项通过，包括大水波保留与不调用脚步粒子。
- 120 Hz 活跃动作检查通过。旧关闭分支原有五秒轨迹受采样率影响；初始测试把 15/30/60 Hz 的范围错误用于 120 Hz。对照合并前控制器得到眼高 0.548 m，整合版 0.531 m；仅修正旧分支测试范围并定向复测 5 项通过，没有改旧浮力算法。
- 手指姿态与 480 个缓坡脚部样本通过。脚部修正与材质仍有明确适用范围。
- 菜单 360 项检查通过，保留 97 个原交互节点（含引擎内部控件）；移动预览绕过通过。布局检查只评价当前可见页面，不把 4.8 隐藏的下拉框搜索输入误判为页面越界。
- 最终导出 PCK 在受控 Jolt 测试池运行 30.6 秒模拟时间，捕获 87 帧/8.7 秒分段动作预览；23 个相关打包资源哈希全部匹配、54 骨姿态与蒙皮结构检查通过、无脚本/渲染错误。它是恒定水面动作夹具，不是完整水体或实时 FPS 测试。已检查泳姿、持物跳跃和第一人称泳姿关键截图；伸臂阶段手可暂时离开视野。
- 同一 PCK 在原泳池通过普通渲染、帧生成开关、硬件光追、跨房间、窗口缩放、DLSS 关闭/重启和设置重载。光追场景 2691 个 TLAS 实例；人物实际淌水 2.09 m，54 骨/动作库/手指数据均有效，没有活跃水花模拟域。光追中的身体、手脚，以及主菜单、水体菜单、画质菜单截图已核对。开关检查不代表额外插帧已验收，见下方实测。

## 正式 EXE 实测与帧生成限制

1920×1080、Ultra 自定义、DLSS Balanced，固定原泳池视角，道具冻结；预热 120 帧后测量 360 帧，全程报告获得焦点。

| 模式 | 基础渲染 FPS | 帧时间 P95 | 实际呈现倍数 |
| --- | ---: | ---: | ---: |
| 帧生成请求开启，光追关闭 | 47.37 | 22.68 ms | 1.00× |
| 帧生成请求开启，硬件光追开启 | 45.57 | 23.37 ms | 1.00× |

NVIDIA 运行库返回成功且功能状态为 active，但本轮完整计数窗口均为 120 个游戏帧、120 个呈现帧，未观察到额外插帧。随后使用同样测试方法复测未修改的 0.6.8 正式 EXE，也得到 1.00×。新旧 EXE 与全部生产 DLL 的 SHA-256 相同。因此目前没有证据将此现象归因于动作补丁，但具体原因尚未确定；不能沿用上一轮约 80 FPS 的呈现结果，也不能将本轮基础 FPS 乘以二。

没有修改驱动、系统设置或引擎来绕过此现象。FG 功能保留，额外插帧效果标为本轮未验证；这里的数据也不构成相对旧版的性能提升结论。原始证据分别位于 output/dlss/motion-release-fg、motion-release-rt、motion-baseline-old-fg。

## 限制

角色仍为程序制作的游戏模型，没有新增皮肤扫描或皮肤法线。人物三角形从 49,653 增为 65,703；不能把这一比例直接换算为整场景掉帧。

脚部对于陡坡、接缝和早期游泳转淌水仍有限制；身体碰撞胶囊保持直立，不覆盖所有伸出的四肢。上游记录的持物落地手腕快速调整仍可能出现。

本次不是全地图长期验收。实验光追首次材质编译可能闪变；透明水面未改成路径追踪；原有退出时 Texture RID 泄漏警告仍存在。测试夹具和正式程序的运行数据分别记录，不混用固定时间录制的 FPS。
