# 水面闪点修复（2026-10-26，替代此前空间滤波方案）

移动视角时，参考水厅的零散高亮斑点在折射分量中存在、纯倒影中没有同样斑点。当前定制引擎在透明水面之后才执行 DLSS RR，原折射读取未降噪的光追池底。旧 3×3 滤波无法消除这条传播路径，现已移除该逻辑。

## 当前实现

- 开启场景 RT 时，水体使用最多 768 像素宽、2× MSAA 的独立光栅捕获作为折射颜色，每帧匹配主相机；原生深度仍负责遮挡、边界和吸收厚度。水面及水花不进入该捕获，避免反馈。
- 此捕获关闭 RT、SSR、SDFGI、SSAO、SSIL，不采用时域历史。保留直射灯、阴影、材质和现有焦散；关闭池底不合理的无遮挡天空镜面反射，避免室内水色发白。主视图与倒影环境、灯光、曝光均不改。
- 光栅主视图保留原屏幕折射；关闭 RT、关闭水体或 Low 水质时停止额外捕获。移动端不创建该相机。场景切换由水体实例管理生命周期。
- 保留上一轮倒影预算：RT 时最多 1024 宽、2× MSAA，RT 关闭恢复用户所选质量；保留人物、淌水波纹、滤镜和全部主线修改。

两套水面着色器还以四个纹理样本积分反射 UV 的像素覆盖范围，减轻被波纹拉细的灯影/栏杆锯齿闪烁；倒影纹理没有 mip 链，因此不能仅更换采样器过滤选项。没有新增粒子或时域反馈。

水下照明现在来自光栅，因此与光追池底的色泽和间接光存在差异。主 RT 仍会追踪不透明池底以产生场景颜色/深度，本修复不宣称移除了主渲染器全部水下 RT 成本。

## 实际检查

RTX 5070 Laptop，1280×720、DLSS Balanced、原生 RT、NR 单层实际执行，FG 关闭。原泳池与参考水厅各 8 项检查通过，包含捕获状态、RT 边界、排除水面、分辨率预算、关闭/恢复和真实淌水移动。使用冻结水波、相同转头轨迹进行 40 帧前后比较，另在水波运行时测量 120 帧耗时。

- 原泳池：17.73 → 18.68 ms/帧。
- 参考水厅：13.13 → 13.83 ms/帧。

以上为短时 CPU/GPU/调度合计帧耗时，不是纯 GPU 时间或全地图保证。此改动目标是去掉噪声传播，额外光栅捕获有成本，不宣称性能优化。原泳池该机位原本的折射闪点不强，不将参考水厅改善比例套用全部场景。

本机证据位于 `evidence/water-sparkle-20261026/`：对比视频左侧为此前版本，右侧为修复；统计方法和水面 ROI 见 `sparkle-analysis.json`。滤镜及动态水波另有最终截图。没有全地图逐角度验收或手机实测。

最终包 535 个资源逐项校验；用户配置及存档 hash 保持。已知 `OpTypeForwardPointer` 和退出 7 个 Texture RID 提示仍在，无最终脚本/着色器错误。本轮只更新本地源码与可玩包，不推送、不发布。
