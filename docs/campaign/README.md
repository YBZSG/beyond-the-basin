# 六章下行主线：源码检查点

这是基于 `godot/waterfeel-20261023` / `351fcd6f8f2bb5fe21851482e2526dfa262ef406` 及 Reference Wing 最终五场景更新的主线原型。它不是 Windows 可执行发行包。自定义 NR Windows 引擎仍须另外匹配，官方 Godot 的无窗口检查不能验证 NR、光追或 GPU 水体。

## 路线
1. 无人的值班：原始随机地图八种房型，固定种子 250821，从连通的有限区域找回八件值班物品。
2. 恢复水路：更衣、静浴、天窗、设备四间扩建房，四件维护部件。
3. 回水的方向：三间 Poolrooms 翼厅，三件回水装置。
4. 五间记忆：最终 Reference Wing 的五间参考图场景，五件交接遗留物。
5. 封存的静翼：找回旧目录的三种 Quiet Wing 房型，三件旧馆部件。
6. 光的出口：正式主厅及其四个配套空间，五件最终交接物。

共覆盖 28 种已有房型，其中 20 种为非原始八房型的独立设计。重复随机实例不重复计数。第一章为容纳八种原始房型使用 16 个连通格；其余章节仅保留该章目录。这里的“同一地图”是同一存档、同一主线的分区世界，不是所有房间同时驻留的无缝巨型场景。

## 操作与存档
- 桌面主菜单选择“主线 · 继续下行”，或使用 `--campaign` 启动。
- WASD / 鼠标沿用原控制。靠近并看向物品，按 E 永久收集；模型不能被随手扔掉而卡关。
- HUD 给出下一件物品所在房间和网格坐标。每章起始房有标识明确的下行终端，全部物品齐备后按 E 开启。
- R 返回当前检查点；Esc 菜单及原独立场景入口仍保留。进入独立场景不会删除主线存档。
- 收集、访问检查点及进入下一章均写入 user://campaign_v1.json。损坏存档不自动覆盖，备份恢复只读，写入错误会明确提示并阻止推进。
- 下行采用独立封闭井道的镜头动画，再在遮挡期间替换分区。不是角色真实穿过旧房地板、落到同时存在的下一层。加载界面可取消返回或安全退出。
- 只有下一章房间、水体准备状态和物理落脚点全部就绪后才确认推进。中途退出恢复上章及已收集物品。

## 资产与封缝
新增五种 Blender 正式道具：铜钥匙、保险丝、阀轮、通行卡、图纸。可编辑源文件、生成脚本及独立 GLB 位于 assets/models/campaign 和 tools/blender/campaign，许可见资产 README。

有限地图外边界增加有厚度遮挡壳，底部嵌入地板，墙角互相搭接；保持已有正式场景和参考场景的设计开口。井道同样封闭搭接。没有通过关闭全局光照、反射或压暗画面隐藏漏光。用户截图具体场景与渲染原因尚未复现，不能声称该截图问题已修好。

## 验证边界
Godot 4.6.3 官方版的无窗口状态/存档测试、六章真实房间构建、物理碰撞、局部站位与收集、遮挡判断，以及异步下行协调测试。下行测试的水体/GPU 准备对象是桩，实际 GPU 等待稳定性仍需目标电脑检查。

本地站位检测不是从入口到全部物品的完整寻路证明。尚需玩家逐章走通，检查入口连通、台阶、手感、光照、物品可读性、模型比例、真实水体准备及切换卡顿。未测目标 GPU 帧率，不宣称 60 FPS 或已完成视觉验收。最终章目前显示交接完成，不包含额外地表结局场景。
